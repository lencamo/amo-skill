# Amo Workflow

协调交付阶段及其证据。具体工作使用已有 amo skill 完成。

## 使用场景

- 用户要求完整功能交付、分阶段实施，或继续活跃交付。
- 项目工作流入口为当前任务选择了这套流程。

## 不使用场景

- 独立问答、小改，或独立的方案、诊断、审查请求，没有活跃交付上下文。
- 用户选择了其他工作流。

## 工作流

1. 读取适用的项目规则和交付偏好，再读[交付模块（中文）](references/modules.zh-CN.md)中的阶段职责、证据和交付记录要求。继续前核实实际工作区、分支、运行环境、设计来源及已有任务记录。
2. 新任务先调研，准备方案和必要预览，再集中收集业务决策与执行授权。记录约定范围、验收标准、执行模式和确认点；沿用会话中已确立的决策。
3. 连续模式在方案确认后推进适用阶段；先验页面模式还需在业务接入前等待页面验收。进度汇报附成果链接，普通阶段更新不变成审批请求。
4. 按名称选择并读取适用的已安装 skill：方案用 feature/improve，带入口引导及关键交互的界面方案预览用 preview，按需用 best/detail/research，编码用 implement，功能审查用 review，已有意见核实用 check，根因未明的诊断用 fix，内容用 draft，最终验收与交付收尾用 deliver。保留各自职责和输出约定；所需 skill 不可用时说明覆盖缺口，不声称已运行。
5. 在已批准的实施范围内修复核实成立的缺陷，重复受影响检查。只有新证据改变既定行为或范围时才重开设计决策。仅审查或核实意见的请求保持只读，除非也获准修复。
6. 阶段切换、重要决策、中断及交接时更新交付记录。恢复时与当前代码、配置和环境对照，仅重查失效证据。回答插入问题后恢复活跃阶段，除非用户停止或改向。
7. 进入最终验收与交付收尾时，读取并使用 amo-deliver，无需用户再次调用。传递目标、当前证据、交付偏好、授权和待办步骤，由其协调体验、独立终审、修复与验收。沿用已有交付记录，仅记录实际执行且获准的收尾结果。

## 关键规则

- 授权来自明确指令及适用项目规则；记录来源和范围。记录本身、方案确认或“继续”不会增加 Git、外部写入、生产或委派权限。
- 区分 Agent 验证、用户验收、提交和部署状态。跳过阶段说明原因，无法检查的部分记录缺口；最终验收时请用户决定实质未决缺口，不得改称通过。
- 必须新增业务选择、扩大范围或权限、缺少 Agent 无法补齐的条件时才中断；等待回答时继续独立且已授权的工作。相同阻碍经过一次针对性恢复仍无新证据时，保存状态并报告，不重复无效重试。
- 针对最终改动及关联调用方审查，不能只引用早期测试结果。外部意见先核实，确认问题后进入单独修复步骤。新缺陷重开受影响阶段，不重启整个交付。
- 记录和证据存入项目指定位置，优先使用已有文档。记录成果路径和环境用途，不存凭证或令牌；可复用 skill 不写入项目专属路径或工具假设。
- 这是由当前 Agent 执行的指令工作流，不是调度器。停止时保存可恢复的下一步，不承诺无人值守或自动唤醒。
