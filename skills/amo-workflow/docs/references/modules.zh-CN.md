# 交付模块

根据当前任务使用适用的阶段。交付记录保留全部八个阶段的状态；不涉及的阶段标明原因，不凭空增加工作。下表规定完成证据，不代表必须向用户请求八次确认。

| 阶段 | 要完成的工作 | 可查看的成果 | 完成条件 |
| :--- | :--- | :--- | :--- |
| 1. 核定需求与现状 | 阅读需求及设计状态；在正确项目、身份和租户下，检查实际代码及相关运行页面。区分可复用、需修改、新增和未核实能力，说明真实入口。 | 功能范围、现状与改动清单、依据及未决业务问题。 | 已有足够证据提出方案，剩余未知项明确列出。 |
| 2. 讨论方案与预览 | 讲清用户、运营和系统流程，明确共用行为、数据契约、迁移、验收标准和部署依赖。界面变化需要具体决策时，使用 amo-preview 基于实际检查的界面制作可交互 HTML 方案，展示可发现的入口路径，用圆角橙色虚线标记必要入口和实际变化，并演示本地场景交互。集中确认规则、页面方向、执行模式、确认点和允许的操作。 | 方案及必要的可点击预览入口、代表性截图和覆盖限制，区分已确认决策与建议。 | 用户已确认适用方案和执行边界；已有明确确认同样有效。 |
| 3. 还原真实页面 | 查看设计标注、相关状态及已有组件。在授权范围内验证素材上传和回读链路，适当复用顶部及组件，在目标技术栈中实现原生页面。将实际渲染状态与已确认设计、适用时已验收的预览和规则对照。 | 运行页面入口、状态截图、设计对照，以及演示数据与真实数据的区分。 | 已在运行环境检查适用状态；先验页面模式下还需用户验收。 |
| 4. 接通业务闭环 | 接通后台配置、API、数据存储和状态流转，替换演示响应。按项目迁移机制准备结构变更，保留受影响的既有流程。 | 已接通的实现、数据来源映射、必要迁移及针对性验证。 | 核心链路具备端到端联调条件，剩余限制已有记录。 |
| 5. 完整联调与体验 | 使用实际实现和可复现的准备步骤搭建隔离环境。走通运营配置、用户操作、后续处理和相关失败分支，区分真实依赖与替代实现。 | 可用环境、不含秘密信息的访问说明、体验步骤、预期结果及实际观察结果。 | 已通过参与流程的各个界面走通核心链路；界面及依赖验证缺口仍明确列出。 |
| 6. 审查与意见核实 | 应用 amo-review 的适度审查标准。需要独立审查时，使用 amo-deliver 的审查步骤，不提前启动最终用户验收，也不额外执行一轮 amo-review。使用 amo-check 核实返回意见，将有效证据交给阶段 8。 | 具体缺陷、实质缺口及审查证据，或独立审查不适用的原因。 | 范围内问题已评估并转入修复或验收；无发现或有依据的低风险豁免均有效。 |
| 7. 修复与重新验收 | 修复已获准处理的缺陷，复现相关触发条件，检查受影响的既有行为，更新已失效的证据。 | 修复结果及当前有效的验收材料。 | 必须修复的缺陷已解决；未解决或延期处理的限制明确交给用户决定。 |
| 8. 验收与交付收尾 | 使用 amo-deliver 协调最终体验、按风险决定是否通过本地 Claude /code-review 执行独立审查、意见处理、修复及用户验收。复用阶段 6 的证据，Orca 负责会话执行和报告回传。展示范围与剩余限制。验收后执行已授权收尾，说明适用的迁移、部署及回退事项。 | 验收记录、实际提交及同步结果、包含与排除文件、发布交接材料。 | 用户验收和已授权收尾结果已有记录；等待授权不能视为完成。 |

## 方案确认点

设计与规则足够明确时，推荐连续执行。用户要求先验页面，或需要在业务接入前判断页面方向时，采用先验页面模式。用具体预览解决实质不确定性，不提出空泛的确认请求。

## 交付记录

沿用已有任务规格和工单系统，增加简短的交付记录，不另建并行跟踪文档。记录位置按项目规则选择；没有约定时，在向已约定工作区之外持久化前与用户确定位置，同时继续有用的调研。

以下字段记录事实，适用时附证据链接：

| 字段 | 内容 |
| :--- | :--- |
| 目标与边界 | 目标行为、排除范围、验收标准及未决业务选择。 |
| 已确认决策 | 已约定的规则和设计方向，以及确立它们的会话或指令；区分用户确认、建议和假设。保留影响决策的业务含义及当前用户可见效果，使后续阶段沿用同一解释。 |
| 执行约定 | 连续执行或先验页面、必要确认点，以及实施和各项独立操作的授权来源与范围。 |
| 工作上下文 | 实际仓库、工作区、分支或版本、环境用途、数据存储，以及真实和模拟依赖。 |
| 阶段进度 | 阶段1—8分别记录：待开始（pending）、进行中（active）、Agent已验证（agent-verified）、等待用户（awaiting-user）、用户已验收（user-accepted）、受阻（blocked）或不涉及（not-applicable）；附成果与验证限制。 |
| 问题与修复 | 触发条件、证据、处理决定、修复状态及受影响检查。 |
| 审查与验证证据 | 审查者身份及完成状态、基线／目标及覆盖范围、验证命令与结果／日志，以及相关环境。实施、审查和收尾共用这份记录，仅更新因改动失效的证据。 |
| 后台资源（存在时） | 本任务所属后台检查及审查会话的句柄、用途、当前状态、需保留的开发／验收服务及访问入口，以及未完成清理的原因和下一步。恢复时先核实这些信息，再重试或释放资源。只记录本任务需要管理的资源，不盘点整机进程。 |
| 收尾 | 拟包含和排除的文件、临时配置、用户验收及实际 Git／发布结果。 |
| 恢复信息 | 下一步、待回答问题或待满足条件，以及最近更新时间。 |

不得将 Agent 已验证的阶段标为用户已验收。项目使用实现工单时继续保留相关工单；交付记录只作汇总并链接到这些工单。
