# Amo Preview

沿用产品现有界面语言，让用户从起始页面找到已讨论的界面变化、看清效果并完成关键操作。

## 使用场景

- 用户希望在实施前找到拟改功能的入口、查看最终界面并体验关键交互。
- 交付工作流需要具体预览来确认界面决策。
- 用户要求修改已有方案预览。

## 不使用场景

- 首要任务是决定新功能的业务设计；先明确方案。
- 用户要求生成插画、实施生产页面或审查已有体验。
- 用户明确要求仅静态产物；直接遵从该格式。

## 工作流

1. 阅读已讨论方案、已定决策、项目规则和已有预览，再读[预览交付规范](references/preview-contract.zh-CN.md)中的路径、标记、产物和验证要求。
2. 使用可用的浏览器、设备或运行时工具，在正确项目及身份下实际检查相关界面；设计稿和代码作为补充。无法检查时说明缺口，仅按任务和项目规则允许的方式使用提供的参考，不声称已匹配未检查的界面。
3. 梳理熟悉的起始页面、必要入口和中间步骤、实际变化及结果状态。按规范中的保真要求明确各界面的变更范围；实质业务不确定性交由方案负责人决定。
4. 按规范制作适合实际平台及决策的本地交互 HTML。根据检查到的产品和已约定参考生成所需页面、组件或弹窗，不套用固定业务示例或页面数量。
5. 沿路径落实规范中的入口引导和变化标记，包含本身保持不变的必要入口。
6. 将预览中的既有页面与已检查的原界面及变更范围对照，再从约定起点沿所展示的用户路径操作。操作相关状态、标记开关和重置，检查渲染结果并保存代表性截图；无法检查的部分记录为缺口。
7. 通过宿主支持的渲染器或可用本地入口展示可点击产物，附简短起点及操作说明。修改时更新同一预览，并说明前后截图对应的版本。

## 关键规则

- 只实现已约定的预览范围。预览与生产源代码修改、发布及业务写入分开；预览请求不授权这些操作。
- 演示动作使用合成数据和本地状态，保留足够共享状态以展示跨页面结果；示例保存或履约操作不连接真实接口。
- 业务界面放产品内容，预览外围放审阅控制。变更标记和展示遵循交付规范，不把实施说明加入业务页面。
- 合适时按可用可视化渲染器的自身说明复用；不假定必须存在某个宿主 SDK，产物仍需可用。区分已验证行为、模拟行为、未验证样式及运行限制。
