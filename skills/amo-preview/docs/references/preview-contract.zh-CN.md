# 界面方案预览交付规范

预览应让用户回答：从哪里进入、具体改什么、怎样操作？这些目标适用于实际的网站、移动端、后台、页面、组件或弹窗场景。

## 现状证据

选择视觉参数前，实际检查相关既有页面，保留入口、项目及身份上下文和代表性截图。识别导航、内容宽度、组件形态、颜色、字体、间距和重要交互模式。匹配项目实际主题；此前预览随宿主出现的明暗外观，不是通用配色。

区分实际检查的产品行为、设计参考和拟变更。没有既有页面时，使用已约定设计参考并注明新增界面。不能把早期原型的截图当成原系统实页。

## 变更范围与保真

- 制作前，简要明确每个预览界面中保留的元素，以及新增、调整、替换、合并或删除的内容。变更须对应用户需求或已定方案，记录在工作笔记或已有任务记录中。
- 变更范围外，保留已检查界面的布局、导航、内容、控件、术语、初始状态及共享业务场景。需求或方案已支持的替换、合并和删除直接执行，不重复询问；涉及实质业务决策或扩大范围时，先解决再作为已定内容展示。
- 合成数据须覆盖相关的既有场景，例如平台或账号来源，同时覆盖新增场景。减少示例数据不能缩窄所展示页面的能力。

## 入口路径与标记

- 从约定且用户能识别的页面开始，保留到达改动所需的导航。覆盖相关菜单、原有按钮、中间页面和弹窗构成的路径。深链接、孤立的最终弹窗或预览专用页面切换器，不能替代这条路径。
- 必要入口和实际新增／调整区域都使用圆角橙色虚线标记。原控件即使保持不变，也要标出必要入口。用简短预览标注或图例区分“从这里查看改动”和“实际改动区域”；入口标记不表示该控件已修改。
- 每一步显示相关的下一层入口，到达后显示实际变化。标记范围跟随当前路径和可见状态，包括弹窗，不标无关控件。移动或删除元素时展示原位置或注明的前后对照，让用户仍能定位变化。
- 标记默认开启，并提供统一开关以查看干净界面。使用覆盖层或同等方式，保持原产品布局、组件外观、焦点和点击目标；所有展示尺寸中均保持圆角橙色虚线。

## 产物

- 默认交付可交互 HTML，页面、组件、弹窗和展示尺寸由实际平台及决策决定。不要求后台外壳、固定页面组合或示例业务。生成足够连贯的内容和视觉细节，便于判断最终效果；稀疏的交互测试页不满足要求。
- CSS 和 DOM 查询限定在预览内，适当使用本地脚本及素材，小型预览不要求新建应用框架。内嵌时遵守宿主渲染器的封装规则，提供产物实际可打开或运行的入口。
- 使用连贯的合成场景，金额、文案和状态由本地数据推导。演示保存或状态变化后，其他相关页面同步反映结果，并能重置到起始场景。说明哪些控件可演示、哪些不在范围内。
- 未模拟行为的控件保留原有外观和状态。在预览外围说明限制，也可在控件触发时说明，但不执行真实操作。不能因为未模拟就省略控件或随意禁用。
- 标签、按钮、弹窗及表单支持键盘焦点和可见校验。沙盒禁止表单提交时，使用带校验和键盘支持的显式本地操作处理。演示影响当前决策的空态、禁用、确认、成功或失败状态，不实现无关导航。
- 产物不含凭证、真实客户资料或服务调用。示例动作，包括表单提交及上传控件，全部留在本地。使用已获准的非敏感素材；新取远程素材仍遵守任务授权。

## 预览外围与展示

预览外围放简短的场景／示例数据说明、路径指引、标记控制和重置。需要审阅多个界面时才增加页面切换。画布内保持正常产品文案，引导标签作为预览标注呈现，不作为生产内容。

交付可点击预览，附代表性截图作为证据。宿主支持时优先会话内嵌；否则提供可用本地入口并说明展示限制。默认交互产物不能只用静态截图替代。无法实际运行查看时，交付产物并说明验证缺口，不声称已操作检查。

修改时尽量沿用同一产物入口，保留不受影响的已定行为，简述本次要求的变化。前后截图对应实际产物版本，明确区分原系统截图和预览截图。

## 验证

在相近的展示尺寸和状态下，将预览中的每个既有界面与原界面对照。核对遗漏、移动、改名、替换、合并和状态变化是否符合变更范围，适用时包含滚动或展开后才出现的内容。修正没有依据的差异；新增交互能运行不代表界面保真。无法检查原界面时，将保真标为未验证。

从约定起点打开产物，通过展示出的产品入口到达改动；适用时包含未修改的触发控件。检查下一步是否可发现、最终界面是否足以判断效果，以及关键操作是否产生预期本地结果。沿路径核对标记用途、形状、颜色、可见性及点击是否受阻。

在预期审阅尺寸检查实际布局，操作适用的字段编辑、确认／取消分支、状态同步、干净视图开关，以及重置回起点。检查运行时没有向生产发送业务请求、表单或导航。

只对实际操作过的交互声称行为验证通过；这不能代替对缺失或被改动元素的原界面对照。如实说明检查过的现状、操作路径、合成行为和缺失覆盖。方案预览用于设计决策，真实页面和业务验收仍属于后续交付阶段。
