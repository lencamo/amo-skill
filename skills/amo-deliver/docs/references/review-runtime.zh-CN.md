# Orca 与本地 Claude 审查

仅使用 Orca worker 或内置本地 Claude `/code-review` 时读取。用户未指定且项目未要求时，这个运行时是可选项。

## 分配任务

- 使用 Orca 前读取 orchestration skill 和对应版本的运行时指南。采用全新独立审查会话，遵守所选审查者和已配置模型。直接审查时，让 worker 自己应用 amo-review，不再启动另一个审查者。
- 选择本地 `/code-review` 时，使用内置命令，不使用旧 GitHub 插件、云端 Code Review、ultrareview 或 OCR delegate。按具体风险选力度：范围明确的低风险改动用 `low`，常规功能用 `medium`，敏感或复杂行为用 `high`，只有明确深入分析需要时用 `max`。简短解释选择，遵守指定力度，不依次跑各档。
- 连续已提交范围使用 `/code-review <effort> <base-sha>..<target-sha>`，基线解析为适当共同祖先。保留明确选择的提交及包含的工作区改动，不替换范围。
- worker 及任何内置子流程均须只读，不运行测试／构建或修复。内置结论返回后，外层仅可解决影响结论的证据歧义，不重复范围内审查或另写一份长报告。及时返回结论与实质缺口。

## 完成与清理

- 遵循运行时完成协议，要求协调者结束轮次时照做。后台启动或任务句柄不等于审查完成，收到真实发现后才报告完成。通过运行时返回结果，不要求用户复制。
- 保留输出；如曾启动测试／构建，核对所属句柄。资源紧张时先停止审查所属验证再诊断。取消时，通过运行时归属／取消协议停止被派工 worker 及其所属子进程，确认退出后才声称已停止。归属或退出不明时报告缺口。保留无关会话、用户接管、要求保留的终端和仍需要的开发／验收服务。用户未指令时不重启已取消工作。
- 按当前运行时指南自动或显式释放归属已确认的专用终端；待释放不等于已释放。终端释放、临时工作区清理与日志保留分别处理，不以删除工作区或日志作为释放终端的条件。
- 清理状态与审查结果分开。释放失败不使已完成结论失效，也不要求再审。仅针对失败操作按支持的恢复流程处理。确认前一次 worker 已停止后，才在同一任务上重试，遵守限制，不新建任务绕过。
